## 개요

김정재의 포트폴리오는 프로젝트 썸네일을 나열하는 대신, 각 작업이 어떤 문제에서 출발했고 어떤 판단을 거쳐 현재의 형태가 되었는지를 문서로 설명한다. 이 방식은 결과물과 작업 과정 사이의 관계를 보존하고, 시간이 지난 뒤에도 결정의 맥락을 다시 찾을 수 있게 한다.

이 Wiki의 문서는 서로 연결된다. 인물 문서에서 프로젝트, 기술, 연표로 이동할 수 있고, 각 프로젝트 문서에서는 관련 기술과 작업 시기를 역으로 확인할 수 있도록 구성한다.

## 활동

주요 활동은 디지털 제품의 화면 구조를 설계하고 이를 실제로 동작하는 인터페이스로 구현하는 일이다. 작업 과정에서는 시각적 완성도뿐 아니라 정보 구조, 반복 가능한 운영 방식, 문서의 유지보수성을 함께 다룬다.

### 작업 원칙

- 결과보다 먼저 해결하려는 문제를 정의한다.
- 사용자가 반복해서 수행하는 흐름을 짧고 예측 가능하게 만든다.
- 복잡한 시스템은 문서와 작은 구성 요소로 나누어 관리한다.
- 기술 선택은 유행보다 목적과 유지 비용을 기준으로 설명한다.

## 기술과 도구

웹 표준을 중심으로 콘텐츠 구조와 표현을 분리한다. 정적 생성, Markdown 문서, 버전 관리처럼 운영 부담이 작은 도구를 선호하며, 상호작용이 필요한 부분에만 클라이언트 코드를 추가한다.

긴 주소와 기술 식별자가 레이아웃을 깨지 않는지 확인하기 위한 예시로 `https://example.com/projects/kimjeongjae-wiki/architecture-and-interface-decisions`와 같은 문자열도 문서 흐름 안에서 처리한다.

## 기록 방식

문서는 개요, 배경, 구현, 결과, 관련 문서, 각주의 순서로 작성한다. 제목은 검색과 연결에 유리한 명사형을 사용하고, 날짜와 분류는 문서 데이터에 별도로 저장한다. 내용이 달라져도 화면 구조를 복사하지 않도록 모든 문서는 같은 셸을 공유한다.
